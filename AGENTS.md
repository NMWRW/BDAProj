# COSC760 Financial Risk Using NLP

This Big Data Analytics project aims to assess financial risk from the narrative in public SEC EDGAR filings. The pipeline acquires original filings, extracts text by filing section, and prepares that text for downstream NLP. Read the [changelog](CHANGELOG.md) for the current work, verification, and next step.

## Pipeline and repository map

| Path | Role |
| --- | --- |
| `scripts/acquire_sec.py` | Finds filings by ticker or CIK and downloads primary documents. Each run writes a manifest with filing identifiers, dates, source URLs, and checksums. |
| `scripts/parse_sections.py` | Parses primary filings offline. It identifies sections by part and item number and writes one narrative CSV and one companion table CSV per filing. It accepts a completed acquisition manifest or a single filing with an explicit form. |
| `scripts/validate_sections.py` | Independently compares Risk Factors and MD&A with original HTML for the validation sample and writes JSON evidence plus an optional Markdown report. |
| `docs/` | Comparison reports with per-accession findings and audit limits. |
| `data/sec/` | Local acquisition runs with the original filings and manifests. |
| `data/parsed/` | Local section and table CSVs generated by the parser. |
| `tests/` | Offline acquisition and parsing tests, with additional checks when local filings are available. |
| `README.md` and `requirements.txt` | Setup, command examples, and the Beautiful Soup dependency for parsing. |

## Working with the pipeline

- Run commands from the repository root with Python 3.10 or newer. Install the parser dependency with `python3 -m pip install -r requirements.txt`. Acquisition uses the Python standard library.
- Set `SEC_USER_AGENT` to a project identifier and a real contact email when downloading. Use completed manifests as batch inputs and keep original filings intact. Raw and parsed data stay local under the Git-ignored data directories.
- The parser handles the primary HTML filings for 10-K, 10-Q, and 8-K, including amendments. Plain-text filings and exhibits are outside the current pipeline. An 8-K's substantive disclosure may be in an exhibit.
- Use `*_filing_sections.csv` for narrative and `*_filing_tables.csv` to audit separated tables. Keep the filing identity and the part/item pair when joining outputs. Item numbers can repeat across parts, and heading text can vary across filings.
- Preserve prose in layout tables and numbers in narrative sentences. Table classification and heading detection use heuristics, so compare output with source filings when testing a new layout.
- Run `python3 -m unittest discover -s tests -v` after pipeline changes. Update the [changelog](CHANGELOG.md) when the active work or its next step changes.
